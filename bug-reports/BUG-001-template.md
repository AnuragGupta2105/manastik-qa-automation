Create a bug report only when an issue has been observed and can be investigated.



1\. Issue Summary



Bug ID: BUG-XXX



Title: Brief description of the observed failure



Status: Needs Investigation / Reproduced / Fixed



Severity: Low / Medium / High / Critical



Priority: Low / Medium / High



2\. Test Environment



Application: Manastik Medico



Package: com.manastik.dadtmedico



Platform: Android Emulator



Device ID: emulator-5554



Android version/API level: Record actual value



Application version: 3.21.5 (confirm the installed build)



3\. Preconditions



Record the initial application state, required test data, and any setup needed to reproduce the issue. Do not include passwords, OTPs, or personal information.



4\. Steps to Reproduce



Start from the documented initial state.



Perform the action that triggers the issue.



Continue until the unexpected behavior appears.



5\. Expected vs. Actual Behavior



Expected: Describe the behavior required by the relevant test case.



Actual: Describe exactly what happened, including any displayed message or unexpected screen.



6\. Impact Assessment



Severity: Based on the effect on application functionality.



Priority: Based on the urgency of investigation or resolution.



User impact: Explain which user action or workflow is affected.



7\. Supporting Evidence



Screenshot or recording



Relevant sanitized logs



Related test case ID



Automation output, if applicable



8\. Reproducibility and Investigation



Record the number of attempts and how many reproduced the issue. Check whether the behavior could be caused by the automation script, emulator state, network, or test data.



9\. Resolution and Retest



Record the fix, if any, and the result of retesting. Keep the report open if the issue remains unresolved.



QA reporting standard: Do not classify an observation as an application bug until it has been reproduced and distinguished from an automation, environment, network, or test-data problem.
